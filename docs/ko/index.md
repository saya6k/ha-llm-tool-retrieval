# LLM 도구 선별 — Home Assistant 통합

> Home Assistant **2026.12.0.dev202611220217** 이상이 필요합니다.

> 기준 문서는 [English](../en/index.md)이며, 이 번역은 늦을 수 있습니다.

대화 에이전트에 LLM API를 여러 개 선택하면 요청마다 모든 도구가 모델에
전달됩니다. MCP 서버 몇 개만 붙여도 백 개가 훌쩍 넘습니다. 토큰과 시간이
들고, 모델이 보는 도구가 많을수록 엉뚱한 도구를 고르는 일도 늘어납니다.

이 통합은 에이전트가 원래 API들 **대신** 선택하는 LLM API를 등록합니다.
요청마다 다음 도구만 넘깁니다.

- **기기 제어의 기본 도구**: 켜고 끄기, 타이머, 미디어, 날짜, 현재 상태
  조회처럼 짧고 일상적인 요청을 다루는 도구
- **항상 포함**하도록 지정한 도구
- 그 밖의 모든 도구 중 사용자의 말과 **의미가 가장 가까운 도구** `top_k`개
  (기본 8개)

의미 비교에는 [Embedding](https://github.com/saya6k/ha-app-embedding) 앱 같은
OpenAI 호환 임베딩 API를 씁니다. 도구는 원본 그대로 전달되므로, 음성
위성이 보여주는 카드를 포함해 도구 결과는 전과 똑같이 도착합니다.

한국어 요청 41개를 도구 177개에 대해 측정했을 때, 정답 도구가 넘겨진 도구
안에 들어온 비율은 영어 설명만으로 93%, 한국어 한 줄 요약을 더하면
98%였습니다([AI Task 요약](#ai-task-요약) 참고). 요청마다 전달되는 도구는
약 167,000자에서 약 17,000자로 줄었습니다.

## 설치 (HACS)

1. HACS → ⋮ → **Custom repositories** →
   `https://github.com/saya6k/ha-llm-tool-retrieval`을 **Integration**으로 추가
2. **LLM Tool Retrieval**을 설치하고 Home Assistant 재시작
3. 설정 → 기기 및 서비스 → **통합 추가** → "LLM Tool Retrieval"

## 설정

| 설정 | 기본값 | |
|---|---|---|
| 이름 | Tool retrieval | 에이전트의 LLM API 목록에 표시되는 이름 |
| 원본 API | — | 이 API가 도구를 골라 올 API들 |
| 임베딩 서비스 주소 | — | `/v1`까지 포함. Embedding 앱이면 `http://<hostname>:8080/v1` |
| API 키 | — | 선택. Bearer 토큰 |
| 요청마다 고를 도구 수 | 8 | 항상 포함하는 도구 외에 추가로 |
| 기기 제어의 기본 도구 항상 포함 | 켜짐 | 기기 제어에 노출된 스크립트는 다른 도구처럼 의미로 고름 |
| 항상 포함할 도구 | — | 에이전트가 보는 도구 이름. 예: `search`, `save` |
| 사용자 언어로 요약을 쓸 AI Task | — | 선택. 아래 참고 |
| 질의 접두어 | `task: search result \| query: ` | EmbeddingGemma용. 다른 모델이면 비움 |
| 도구 텍스트 템플릿 | `title: {title} \| text: {text}` | EmbeddingGemma용. 다른 모델이면 `{text}` |

그다음 대화 에이전트 설정에서 **원본 API들을 해제하고 이 API만 선택**하세요.
둘 다 선택하면 같은 도구가 두 번 들어갑니다. 엔티티 노출 설정은 그대로
적용되어, 기기 제어는 Assist에 노출된 엔티티만 봅니다.

필요한 원본 조합마다 항목을 하나씩 만들 수 있습니다. 예를 들어 음성
비서용 하나, 원본을 더 넣은 텍스트 에이전트용 하나.

### AI Task 요약

도구 설명은 대부분 영어입니다. 요청이 다른 언어로 들어온다면 AI Task
엔티티를 지정하세요. 도구마다 Home Assistant 언어로 한 줄 요약을 쓰게 하고,
설명과 함께 임베딩합니다. 이 요약은 모델에게는 보이지 않습니다. 도구마다 한
번만 쓰고, 설명이 바뀔 때만 다시 씁니다.

## 한계

- **대화의 첫 요청이 그 대화의 도구를 정합니다.** Home Assistant는 대화마다
  API의 도구를 한 번만 받아 이후 턴에도 그대로 씁니다. 같은 대화에서 다른
  주제로 이어 말하면 그 도구가 없을 수 있습니다. 음성 요청은 대개 한 턴이라
  문제 되는 일이 드뭅니다.
- **보안 경계가 아닙니다.** 요청과 맞는 도구라면 무엇을 하든 넘깁니다.
  브라우저나 코드 실행처럼 요청 한마디로 실행되면 안 되는 도구가 있는 API는
  원본에서 빼세요.
- **실패하면 모두 엽니다.** 요청 문장이 없을 때(예: AI Task), 임베딩 서비스가
  5초 안에 답하지 않을 때, 아직 임베딩하지 않은 도구는 숨기지 않고 넘깁니다.
- 관리자 전용 API(예: Home Assistant)는 관리자에게만 넘깁니다. 다른
  사용자에게는 건너뛰고, 나머지 원본은 그대로 동작합니다.

## 서비스

### `llm_tool_retrieval.preview`

어떤 요청에 어떤 도구가 넘겨지는지, 의미로 고른 도구마다 유사도 점수와 함께
보여줍니다. `top_k`와 항상 포함할 도구를 정할 때 씁니다.

```yaml
action: llm_tool_retrieval.preview
data:
  config_entry_id: 01K...
  text: 거실 불 꺼줘
# reason: ranked | no_query | few_tools | embedding_unavailable
# available / selected: 도구 수
# pinned: 항상 포함된 도구
# ranked: [{tool, score, selected}] 점수 높은 순
```

## 동작 방식

시작할 때와, 요청이 처음 보는 도구에 닿을 때마다 각 도구를 이름과 설명 앞
300자(요약이 있으면 요약도)로 임베딩합니다. 벡터는 저장해 두고, 그 텍스트가
바뀔 때까지 다시 씁니다. 요청마다 사용자의 말을 한 번 임베딩해(CPU에서
EmbeddingGemma로 약 40ms) 저장된 벡터와 비교합니다.
